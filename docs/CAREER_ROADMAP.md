## 0. 먼저 — 전략 (이것만은 꼭)

### ① 퍼블리셔 9년은 "버리는 경력"이 아니라 **해자(moat)** 다
신입~주니어 프론트엔드가 가장 약한 곳이 바로 당신이 9년간 한 것이다:
- 시맨틱 마크업 / 웹표준 / **접근성(a11y)** / SEO
- **반응형·크로스브라우징**, CSS 레이아웃(flex/grid), 애니메이션, 디자인 감각
- 디자이너·기획자와의 협업 경험, 픽셀 단위 구현력

→ 이력서/면접에서 **"퍼블리셔 출신이라 마크업·CSS·접근성·디자인 협업이 강한 프론트엔드"** 로 포지셔닝한다. 신입과 경쟁하는 게 아니라 **"퍼블리싱 되는 프론트엔드"** 라는 희소 포지션을 노린다.

### ② 채용공고의 스택 나열에 압도되지 마라
`react, vue, next, java, spring, typescript, python, node` — 이건 "다 잘하라"가 아니라 **"우리 회사 환경은 이렇다"** 는 안내다. 실제로 한 사람이 다 깊게 하는 경우는 없다. **대입해서 3등급으로 나눈다:**

| 등급 | 스택 | 목표 깊이 | 이유 |
|---|---|---|---|
| 🟢 **주력 (깊게)** | **React · TypeScript · Next.js** | 실무 가능 / 혼자 서비스 구현 | 한국 프론트 채용의 70%+. 이미 `react-portfolio`로 시작함 |
| 🟡 **협업 (읽기·연동)** | **Node.js · REST API · Git** | 읽고 고치고 연동 가능 | 프론트와 같은 JS. BFF·도구·API 연동에 직접 쓰임 |
| ⚪ **교양 (면접 대응)** | **Java/Spring · Python** | "백엔드가 뭘 하는지 안다" | 직접 개발 X. API 문서 읽고 협업할 정도면 충분 |
| 🔵 **선택 (나중·조건부)** | **Vue** | 특정 회사 타겟일 때만 | React 굳히기 전엔 손대지 말 것 (둘 다 어설프면 마이너스) |

> **핵심: React를 "깊게" 끝내기 전에 Vue·Spring·Python에 시간 쓰지 마라.** 어설픈 5개보다 확실한 1개 + 협업 가능한 1개가 취업에 강하다.

### ③ 너에겐 이미 출발점이 있다
`react-portfolio` + `/study`(React/TS/Sass 레슨) + `/lab`(WebGL) — 이미 **"학습을 증명하는 자산"** 을 만들고 있다. 로드맵은 *새로 시작*이 아니라 *이걸 키우는* 방향이다.

## 1. 단계별 로드맵 (약 6~9개월, 주 10~15시간 기준)

### Phase 0 — 현재 위치 점검 ✅ (이미 진행 중)
- [x] React + TS + Vite + SCSS로 SPA 구현·배포 (`react-portfolio`)
- [x] 학습 콘텐츠화 (`/study`), WebGL 학습 착수 (`/lab`)
- **→ 지금 할 일**: [SKILL_ASSESSMENT.md](./SKILL_ASSESSMENT.md)의 1~2순위 체크리스트로 **기존 코드부터 탄탄하게**. (정합성 정리 → ESLint/테스트/CI)

### Phase 1 — React + TypeScript "실무 수준"으로 굳히기 (6~8주) 🟢
새 걸 배우기 전에 **있는 걸 실무급으로**. SKILL_ASSESSMENT 3순위와 직결.
- [ ] 커스텀 훅으로 추상화 (`useFetch` 등), 로직 재사용 경험
- [ ] 상태를 discriminated union으로, 런타임 검증(`zod`)
- [ ] **테스트 작성**(Vitest + RTL) — 주니어와 가장 크게 벌어지는 지점
- [ ] React 핵심 개념 면접 대비: 렌더링/리렌더, key, useEffect 의존성, 메모이제이션, Context vs 상태관리
- [ ] (도구) Git 브랜치 전략, PR, 코드리뷰 흐름 익히기
- **산출물**: `react-portfolio`가 "테스트·CI 갖춘 깔끔한 React+TS 앱"이 됨

### Phase 2 — Next.js (6~8주) 🟢 ★취업 직결도 최상
SPA 다음의 사실상 표준. **실서비스형 프로젝트 1개**를 새로 만든다.
- [ ] App Router, 파일 기반 라우팅, 레이아웃
- [ ] **렌더링 전략**: SSR / SSG / ISR / 클라이언트 — *언제 무엇을* (면접 단골)
- [ ] 서버 컴포넌트 vs 클라이언트 컴포넌트, 데이터 fetching
- [ ] SEO·메타데이터·이미지 최적화 (← **퍼블리셔 강점과 시너지**)
- [ ] 배포(Vercel)
- **추천 산출물**: 실제 데이터(공개 API 또는 직접 만든 간단 백엔드) 쓰는 서비스 — 예: 블로그/대시보드/검색 앱. 단순 포트폴리오 말고 **"서비스"** 형태로.

### Phase 3 — 협업 역량: 백엔드와 말이 통하는 프론트 (4~6주) 🟡
직접 백엔드 개발자가 되는 게 아니라 **연동·협업** 가능 수준.
- [ ] **Node.js** 기초 + Express/Fastify로 간단한 API 서버 직접 한 번 만들기 (BFF 개념)
- [ ] REST API 설계 원칙, HTTP(메서드/상태코드/헤더/CORS), 인증(JWT/세션/쿠키)
- [ ] 비동기·Promise·fetch 깊이, 에러 처리, 환경변수·보안 기초
- [ ] DB 맛보기(간단한 CRUD) — 백엔드가 뭘 하는지 체감
- **산출물**: Phase 2 프로젝트에 **내가 만든 Node API**를 붙이면 "풀스택 흐름 이해" 증명

### Phase 4 — 차별화 + 백엔드 교양 (병행, 4~6주) 🔵⚪
- [ ] 🟢 **WebGL Lab 계속** ([WEBGL_LAB_PLAN.md](./WEBGL_LAB_PLAN.md)) — Phase 2 셰이더 → Phase 3 성능. **이게 너만의 시그니처**
- [ ] ⚪ **Java/Spring · Python "교양"**: 직접 개발 X. "Spring이 API를 어떻게 주는지", "Python이 어디 쓰이는지"(데이터/AI/스크립트) 개념만. 면접에서 "백엔드 협업 가능합니다" 라고 말할 정도.
- [ ] 🔵 **Vue (조건부)**: 지원하려는 회사가 Vue 메인이면 그때 1~2주 속성. React를 안 상태면 Vue는 빠르게 익는다.

### Phase 5 — 취업 활동 (병행 시작, 상시) 🎯
- [ ] **이력서**: 퍼블리셔 9년을 *프론트 강점으로 번역*("마크업/접근성/CSS/디자인협업이 강한 프론트")
- [ ] **포트폴리오**: `react-portfolio`(메인) + Next 서비스 + WebGL Lab을 한 줄로 꿰기
- [ ] **GitHub**: 꾸준한 커밋 히스토리(잔디), README 정리
- [ ] **기술 블로그**: `/study`에 쌓은 내용을 글로 — "설명할 수 있다 = 안다"의 증거
- [ ] 코딩테스트 준비(자료구조/알고리즘 기초), CS 면접(브라우저 렌더링·HTTP·이벤트루프)

## 2. 추가로 해야 할 것 (기술 외 — 의외로 당락을 가름)

- **CS 기초**: 브라우저 렌더링 과정(Critical Rendering Path), 이벤트 루프, HTTP/HTTPS, 브라우저 저장소, 자료구조·알고리즘 기초(코테용)
- **영어 문서 읽기**: React/Next 공식 문서를 원문으로. 번역 기다리지 않는 습관
- **협업 도구·문화**: Git(rebase/PR/conflict), 이슈 트래커, 애자일/스크럼 용어, 코드리뷰 매너
- **성능·접근성** (← 퍼블리셔 강점을 프론트 무기로): Lighthouse, Core Web Vitals, 시맨틱·ARIA. 이건 **이미 잘하는 걸 프론트 언어로 재포장**하는 것
- **네트워킹**: 개발자 커뮤니티, 컨퍼런스, 스터디 — 전향자에게 레퍼럴은 큰 무기
- **꺾이지 않기**: 9년 경력 전향은 멘탈 싸움이 큼. 단계를 작게 쪼개 "완성한 산출물"을 쌓아 자신감 유지

## 3. 절대 하지 말 것 (전향자 흔한 함정)
- ❌ react·vue·next·spring·python·node를 **동시에** 얕게 — "다 어설픈 사람"이 됨
- ❌ 강의만 무한 수강(튜토리얼 지옥) — **만들면서** 배운다. 산출물 > 수료증
- ❌ 백엔드(Java/Spring)까지 깊게 파려다 프론트가 비는 것 — 너의 타겟은 **프론트엔드**
- ❌ 퍼블리셔 경력 숨기기 — 오히려 **전면에** 내세울 차별점
